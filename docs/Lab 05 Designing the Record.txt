Lab 05: Designing the Record
What does the struct hold? One student's name and that student's scores. Nothing else — apply this morning's rule. If you are tempted to add a field, ask whether it describes the student or describes something the program is doing.
- The structure holds the collections of all students and names

What is fixed and what varies? One of these two numbers belongs inside the struct as a fixed-size array. The other becomes a count that travels with the collection. Decide which, and be able to say why.

    The number of assignments in the course
    The number of students on the roster

What is it called, and where does it live? Which header? Your project already has a module structure from Lab 03 — this type has to fit into it, not sit wherever is convenient. Ask which modules need to see this definition.

How is a collection of them passed? Write the shape a function signature will use to receive the whole roster. You settled this pattern last week; apply it.

Write the old signature and the new one side by side.
For each parameter in the new one, name the reason for its style. A function reading one student does not need the same parameters as one walking the whole roster.
Flag any function whose parameters change but promise does not. Most will be in this group — student_average still returns a mean; it just receives its input differently.
Flag any function whose contract genuinely changes. A precondition about a valid index may mean something different once the count is a parameter rather than a constant.
Ask whether any function should now take one student instead of the whole roster plus an index. Some of them are reaching past five students to look at one.
